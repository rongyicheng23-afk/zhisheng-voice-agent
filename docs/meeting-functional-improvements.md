# 会议主功能改进：查找与批量校正

2026-09-13。本轮修改会议详情页面，复用已有校正 API，不改组员 DeepSeek 网关或共享接口。

## 使用方式

1. 打开已有会议的详情，滚动到“发言片段时间轴”。按关键词或发言组筛选；可以继续使用原有试听、下载和跳转原音。
2. 点击“开始校正”，在“批量校正发言组”选择源组，输入新名称。使用已有组名可把误分的组归为同一显示名称。
3. 查看按钮显示的影响片段数，再点击“应用到草稿”。它处理源组全部片段，不受搜索筛选影响；时间轴和图例即时展示草稿。
4. 核对后点击“保存校正”，沿用现有后端保存与版本记录；筛选外片段也会提交。“取消校正”放弃本次所有草稿变更。

人工名称只用于本场会议整理，不等于声纹身份认证，也不写入声纹注册库。批量修改的草稿移除原相似度展示；后端现有人工校正逻辑继续负责持久化。

## 保存可靠性

- 保存中的重复提交、批量操作和取消操作被拦截。
- 保存请求失败时保留草稿，允许重试。
- 保存成功但历史列表刷新失败时，明确提示校正已保存，并退出编辑，避免错误提示诱发重复版本。

## 后续：后端校正一致性修复

- 校正入口加入 READ_COMMITTED 事务和按会议 ID、用户 ID 限定的行锁，使同一会议的人工校正串行保存；片段、纪要、人工版本写入失败时触发回滚。READ_COMMITTED 避免等锁后仍读到此前用户校验查询建立的旧快照。
- 改名使用专用 SQL 显式置空 speaker_profile_id 和 match_score，不再依赖默认跳过空值的 updateById。只改文本时保留原声学关联；更新条件同时限定片段 ID 和会议 ID。
- 在写入前校验全部片段：无效、重复、其他会议片段整批拒绝，不再静默漏存。
- 前后端仅允许校正 SUCCESS 状态，避免与尚未完成的转写任务相互覆盖。
- 页面不再强制提交未改动的旧全文。片段文字改变时后端可重建全文；仅改名时保留已有全文；用户明确修改全文时以其输入为准。
- 人工版本序列化或数据库写入失败不再伪装成功。
