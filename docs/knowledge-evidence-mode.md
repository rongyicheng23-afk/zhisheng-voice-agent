# 私有资料库与有据原文朗读（2026-09-18）

## 2026-09-29 更新：可选的依据资料归纳

本节为最新行为；下方日期较早的“不调用 DeepSeek / 尚无归纳”描述仅适用于当时版本及现在默认的原文模式。

1. 在语音问答中勾选“资料模式”，默认继续朗读原文，不向 DeepSeek 传资料。
2. 额外勾选“依据资料归纳”，才会把本次问题和最多 3 条已认证检索结果（每条原文最多 500 字，附来源元数据）发送到服务器配置的 DeepSeek 兼容端点。需要有权向该供应商发送这些资料；选项只存在于当前页面。若另行开启自动回答，后续识别完成按所选模式发送。
3. 服务端仅从当前用户有效、已发布资料检索。没有命中直接拒答，不调用模型。DeepSeek 返回结构化 JSON，最多 6 条归纳，每条最多 400 UTF-16 单位、1–3 条不同来源引用。
4. 先收集整个 JSON（最多 16000 字符、60 秒），逐条检查来源 ID、逐字连续原文摘录及结构；通过后才发布来源、归纳文本和音频。未知 ID、虚构摘录、无引用、格式错误、超限和供应商失败均终止本轮，不偷偷改成通用回答。资料不足/冲突可由模型返回拒答，同时保留来源供人工检查。
5. 页面逐条展示归纳、对应原文与来源编号；朗读段落按来源映射高亮。打断同时关闭模型输出流，未检查完的文本不播报；同一连接下一轮清理旧归纳。

准确边界：程序检查的是“引用确实在检索片段里”，不是自动语义蕴含验证、事实认证或可靠的冲突检测。即使引用有效，模型仍可能曲解原文，用户必须核对。系统提示将资料视为不可信数据，但不能保证完全抵抗提示注入。当前仍是关键词检索，尚无向量召回与重排。

兼容性：普通问答的系统提示、流式参数和接口默认不变。归纳专用调用增加 system prompt 与 JSON output 参数；参照 [DeepSeek JSON Output 文档](https://api-docs.deepseek.com/guides/json_mode/)。原文模式仍可不配置 DeepSeek Key。无需数据库迁移，更新后重启实时网关并重新构建/刷新前端即可。未改其他成员分支。

延迟：为了不播出未检查引用，归纳模式需等待完整结构化结果；页面“首次文字”表示检查后首批可展示文字，不是供应商首 token，不应和普通流式问答直接混算。真实供应商效果、授权材料质量和云端 P95 尚待验收。独立人工评测方法见 [knowledge-evaluation.md](knowledge-evaluation.md)。

本轮验证：Java 133 项（真实 MySQL smoke 启用，无跳过）、前端 79 项、实时/评估/ASR Python 90 项、TTS 后端 10 项，共 312 项通过；Java 打包与前端生产构建通过。覆盖模拟模型 JSON 请求与通用模式兼容、认证用户绑定、引用伪造拒绝、无资料不调用模型、生成超时/打断关闭流、检查前无文本音频、前端显式选择与多轮清理、评测分母和无样本情况。本轮没有真实 DeepSeek 或新增浏览器实机验收，不能把模拟语音和测试计数当成真实效果成绩。构建仍有既有包体积、Browserslist 和深度选择器警告。

## 2026-09-28 更新：文件导入预览

资料库提供 `POST /api/knowledge/import-preview`，使用登录 Bearer 令牌与 multipart `file` 字段。提取返回格式、建议标题、正文、PDF 页数和提示，不写知识库，也不上传到外部模型。页面先显示可编辑预览；“应用到正文”之后还需填写发布单位、版本和日期，再保存草稿、核对发布。取消、失败保留原表单；空标题可由文件名填入，已有标题和其他元数据保留。

- TXT：UTF-8，最大100 KB；错误编码和非文本控制字符拒绝。
- PDF：最大5 MB、100页；使用 [Apache PDFBox 3.0.8](https://pdfbox.apache.org/download) 提取文字。加密文件拒绝，纯图片/扫描件提示先做 OCR。部分页面没有文字时返回缺失页数提示，分栏及表格需人工核对顺序。
- DOCX：最大5 MB；提取正文和表格文字，保留插入修订、忽略删除修订。页眉页脚、脚注、批注与图片不导入；旧版 DOC 需要先转换。XML 禁止 DTD / 外部实体，限制 ZIP 条目、解压总量和嵌套深度。
- 正文最大20000个 UTF-16 单位，超限直接报错，绝不悄悄截断。单进程同时最多2个提取请求。前端等待最多30秒；服务端文件/页数/输出限额不等于独立进程级 CPU/内存隔离，公网部署仍应配置入口上传限制和容量测试。
- 引用继续基于核对后保存的段落；不把提取顺序冒充 PDF 原页码。扫描 OCR、向量检索、团队共享及模型有据归纳仍未实现。

验证：Java 133项（含真实 MySQL smoke、无跳过）、前端76项通过；Java打包、前端生产构建通过。MySQL smoke 从临时 DOCX 提取正文，再创建草稿、发布、检索引用并校验个人隔离，最后事务回滚。浏览器在独立本机端口验证了 Word 上传预览、取消保留原正文、相同文件重选、确认应用，以及两页 PDF 的正文和空页提示；未保存浏览器测试草稿。

同轮修复首页误报“在线”：首页改用 `/api/system/status` 的实际探测结果，显示录音转写、实时识别、语音合成、声纹、数据库和存储六项状态，提供检测时间与手动刷新。模型服务未启动时不再因 Java 返回 HTTP 200 而显示正常；网络失败清除旧状态并显示“未确认”。探测通过表示连接成功，不代表完成模型推理测试。

对应第三痛点。当前实现的是“授权检索 + 可追溯原文展示/朗读”，不是向量 RAG，也不是已完成事实核验的大模型回答。资料模式不调用 DeepSeek；原有通用 DeepSeek 模式仍独立保留，不能把通用回答当作有据答案。

## 可用流程

1. 登录，在导航“资料库”录入标题、发布单位、版本、生效日期、截止日期及正文。来源 HTTP/HTTPS 链接可选，不会自动抓取链接。支持粘贴文本、UTF-8 TXT、文字型 PDF 和 Word DOCX 导入预览；扫描件须先做 OCR。请只导入有权使用的资料。文件支持细节见文末 2026-09-28 更新。
2. 正文最多 20000 个 UTF-16 单位（常用中文约 20000 字），TXT 文件最多 100 KB。一个用户最多 100 个资料版本。按换行分段，长段每 500 个 UTF-16 单位切片。来源保存段号及片内偏移，不伪造页码。
3. 新资料保存为草稿，必须人工点击“已核对，发布”。服务端不会自动核实来源真实性，个人发布也不等于管理员审核认证。
4. “创建新版本”保留同一 seriesId，正文不可就地覆盖。发布新版本时同系列已发布版本自动下架，旧版本内容保留。同一系列的版本标签不可重复，可手动重新发布有效的旧版本。
5. 下架、未生效、过期、草稿均不参与检索。日期包含起止当天，以北京时间计算，每次检索重新检查。不同资料的冲突不自动裁决，只展示原文并提醒核对发布方。
6. 页内输入问题进行关键词检索，显示最多三个原文切片、标题、版本、发布方、有效期与段号。当前使用中文双字词/英文词匹配及简单覆盖率排序，未做向量召回、重排或相关性实测。没有命中时明确表示无法确认，不调用模型补编答案。
7. 在实时语音页勾选“资料模式”，输入或识别问题后发送，网关用已认证用户 ID 检索其私人资料并分段朗读原文。资料正文不发送给 DeepSeek；语音仍调用已配置的 TTS 服务。先发送本轮来源字典，再发送文本/音频；每个 segment.ready 的 citationIds 按原文字符区间映射，禁止伪造 ID。页面展示本轮来源卡片，并根据播放器消费的音频段落切换来源高亮（不是按网络到达顺序切换）。
8. 打断、重新录音沿用原轮次取消机制；检索失败时终止本轮，不偷偷改用通用模型。来源是检索时快照，检索后才发生的下架不会追回已经发到浏览器的内容。

## 数据库部署

先在应用自己的 MySQL 数据库执行新增脚本（仅建两张表，无 DROP/清空操作）：

```sh
mysql --host=127.0.0.1 --port=3306 --user=你的数据库用户 --password 你的项目数据库 < minio-backend/springboot-minio/src/main/resources/sql/knowledge.sql
```

密码通过交互提示输入，不写进 Git。数据库应使用 InnoDB 和 utf8mb4。当前这台机器的一键启动使用 `zhisheng_local`，本轮已在该库执行脚本；远程服务器和组员机器需要各自初始化。源码默认数据库 `minio` 不代表当前本机启动器实际使用的库，执行前必须核对。

所有资料操作按登录用户隔离。发布/下架和创建版本在事务内锁定该用户的知识空间，同用户写入串行；状态更新必须携带 revision，过期页面返回 409。没有团队共享接口。下架不等于物理删除，当前没有资料删除/保留期界面。

前后端需要一并更新并重启 Java 服务。资料库文本功能仅依赖登录、Java 和 MySQL，不需要模型。朗读还需要 TTS、参考音频和实时网关；Java 和网关的 `REALTIME_GATEWAY_INTERNAL_KEY` 必须一致。

```sh
bash scripts/start-realtime-gateway.sh
```

启动脚本支持不设置 DEEPSEEK_API_KEY 的资料模式。需要配置 REALTIME_GATEWAY_INTERNAL_KEY、REALTIME_TTS_REFERENCE、合适的 REALTIME_PYTHON；普通模型回答仍需要 DeepSeek Key。配置存在不代表服务已联通，health 字段只是配置提示。

## 接口

- GET/POST `/api/knowledge/documents`：私人资料列表/创建草稿。
- POST `/api/knowledge/documents/{id}/status`：`{status: "PUBLISHED" 或 "WITHDRAWN", revision: 当前版本}`。
- POST `/api/knowledge/search`：`{question: "..."}`，最大 1000 字。
- POST `/api/realtime/internal/knowledge/search`：仅网关凭内部密钥访问，userId 必须来自已消费的登录票据；公网反向代理必须禁止暴露 `/api/realtime/internal/*`。
- WS `/realtime/voice` 的 turn.start 增加可选 `answerMode: "knowledge"`（默认 general），来源事件为 turn.sources。

响应禁止缓存；数据库错误返回固定信息。引用链接仅允许 HTTP/HTTPS，不跟随抓取，不允许 URL 内嵌账号密码。正文和来源在 Vue 中以文本渲染，不执行 HTML 或资料中的指令。

## 2026-09-22 更新：播放来源与安全重试

- 播放器为每段音频记录样本位置，真正消费到该位置时才发送 `playback.segment`；前端关联 `segment.ready.citationIds` 高亮来源。提示语或无依据段落不高亮。暂停等待后续音频时保留当前段落标记；打断、失败、播放完成及新提问清除标记。
- 高亮精度是音频渲染块级，仍受设备输出延迟、主线程调度影响，不代表扬声器实测毫秒同步。段落跨多个来源时可同时高亮，不声称逐字追踪。引用身份重复、未知引用、播放段落乱序均终止本轮；段落映射/播放器标记队列各限制为 256 条。
- 创建资料支持可选 UUID `requestId`。同用户、同编号、同规范化内容重试返回同一版本，不改变已有发布状态；同编号不同内容返回 409。不同用户隔离，事务回滚后可安全重试。沿用原有表结构，无新迁移；旧客户端不传该字段仍可创建，但没有幂等保证。
- 页面保存失败保留正文及请求编号，直接重试沿用编号；修改内容或显式切换新资料/新版本会生成新编号。成功响应去重列表。编号只保存在当前页面内存：刷新、关闭页面后应先查看列表确认是否已保存，再决定新建，不保证跨页面重试去重。
- 自动化回归覆盖播放器消费边界/欠载/打断/队列上限、来源映射拒错、同页重试、HTTP 字段绑定与旧客户端兼容、并发创建、回滚及发布后重试；真实 MySQL smoke 使用合成记录并回滚。未进行真实浏览器扬声器、真实 TTS 或 DeepSeek 端到端验收。

本次需更新前后端并重启 Java、刷新页面；未自动重启用户运行中的服务。原有 DeepSeek 通用回答接口和其他成员分支未改动。

本次最终结果：Java 112 项（真实 MySQL smoke 已启用，无跳过）、前端 57 项、实时/评估/ASR Python 68 项，共 237 项通过；Java 打包和前端生产构建通过。前端仍有既有包体积、Browserslist 及深度选择器弃用警告。首次构建暴露 UUID 类型兼容问题，修复后已重跑；临时 Python 环境缺少 FastAPI，改用项目已有 ASR 虚拟环境完成 Python 回归。

## 2026-09-24 更新：版本核对与安全发布

### 用户流程

1. 资料列表支持按标题、发布单位、版本号及状态筛选：有效且已发布、草稿、已下架、已过期、未生效。筛选不修改资料，不影响服务端检索；日期标签取浏览器计算的北京时间，跨天请刷新，服务器独立校验发布资格。
2. 创建同一资料的新版本后，在“版本对比”选择对照版本和目标版本，查看标题、发布单位、链接、版本号、日期及正文差异。服务端拒绝跨用户或跨资料系列的对比。
3. 点击“预览发布与替换影响”，查看待发布资料、当前已发布且将被下架的版本、差异及完整原文。仅预览不写数据库，取消不修改任何状态。
4. 核对后点击“我已核对，确认发布及替换”。服务器在同一事务中锁定用户知识空间，重新核对候选版本、已发布版本集合及修订号、北京时间日期；任一状态或日期变化返回 409，页面丢弃旧预览，必须重新预览。两个页面同时确认不同版本时，不允许两者都基于同一旧快照成功。
5. 未生效、已过期或已经发布的候选版本不能通过该确认流程发布。成功后自动刷新列表并清理旧检索结果；刷新失败明确提示发布已成功，不诱导再次提交。网络中断导致结果不确定时，也应先刷新列表确认实际状态。

“核对”指用户自行核对，**不是管理审批、真实性认证或政策冲突检测**。当前没有审批角色或持久审计记录；资料模式仍朗读检索原文，不调用 DeepSeek 生成归纳结论。

### 新增接口与兼容性

- POST `/api/knowledge/compare`：`{beforeId, afterId}`，只读，返回信息差异、带原/新行号的正文差异及新增/移除行数。
- GET `/api/knowledge/documents/{id}/publication-preview`：只读，返回 candidate、replaced、checkedOn、eligible、message、reviewToken；恰有一个被替换版本时附带 comparison。
- POST `/api/knowledge/documents/{id}/publish-reviewed`：`{reviewToken}`，执行基于预览快照的原子发布。token 是状态指纹，不是授权凭证，仍必须登录并且拥有该资料。
- 以上接口使用登录用户，忽略调用方自行填写的用户 ID；正常响应 no-store。无需数据库迁移，无新增模型依赖。
- 旧 `/status` 接口保留兼容性，仍只校验候选版本 revision，没有对照版本快照保护。新页面发布只走新流程；需要同等保护的旧客户端必须升级到 preview + publish-reviewed。下架仍走原 revision 接口。

### 比较边界与验收

逐行比较保留空行、重复行和 Unicode；CRLF/LF 换行形式视为相同，行号与检索段号分别编号。精细比较矩阵最多 250000 个单元，超过时保留共同首尾，把中间区块列为移除/新增，明确显示“块级对比”，不宣称最小差异。前端每页最多渲染 100 行，防止大量空行一次性生成海量 DOM。
