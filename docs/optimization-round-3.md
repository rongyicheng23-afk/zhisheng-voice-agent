# 第三批：TTS 输入限制与失败反馈对齐

2026-09-12。基于第一批已确认的限制，补齐现有页面 → Java → XTTS 链路。
这是减少无效等待、明确失败与重试边界的配套改造，不是新增真正流式 TTS。

## 改动

- 页面显示已输入字符数 / 500，超限时阻止提交；按 Unicode 码点计数，避免把普通 emoji 按两个 UTF-16 单元计数。未静默截断或自动拆分文本。
- 页面旧的 50 MB 提示改为：非空参考音频小于 20 MiB，完整上传请求最多 20 MiB（界面沿用 MB 标签）。请求包含文件、文本和 multipart 元数据，文件接近上限仍可能超限。
- Java 共用输入校验，在创建历史/保存参考音频前拒绝空文本、超长文本、空文件及文件超限；直接调用 TTS 服务也执行同样校验。
- Java 发往 XTTS 前检查最终 multipart 请求长度；该检查在当前业务流程中晚于参考音频保存，接近上限的失败请求可能保留失败历史和参考音频，不自动删除。
- 不读取或转发上游错误正文、内部 URL；400/413/429/503/其他失败映射成固定安全提示。网络超时/中断明确提醒服务端可能仍在处理，不宣称已经取消。
- 保持现有 API 封装：HTTP 200 的 R.code 区分业务 400/413/503/502/504；并未将整个接口改为对应 HTTP 状态码。页面现有 response.msg 提示可直接兼容。
- 禁用 TTS OkHttp 连接失败自动重试；页面处理期间重复点击不再次提交，繁忙后由用户手动重试。尚无跨请求幂等键，不能声称解决多标签页重复提交。
- 合成成功响应最多读取 32 MiB + 1 字节，拒绝过短或超限数据；这是长度检查，不是完整音频解码/格式安全验证。
