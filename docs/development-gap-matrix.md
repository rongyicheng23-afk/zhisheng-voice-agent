## 本轮实测入口

在更新后的本地 XTTS 服务运行时，使用已安装 `services/realtime/requirements.txt` 的 Python 环境，并将你有权使用的参考 WAV 作为显式参数：

```bash
python scripts/verify-streaming-tts.py --reference /absolute/path/to/authorized-reference.wav
```

该命令只输出时间和 PCM 长度，不输出音频或文本。`firstChunkBeforeCompletion=true` 说明该次 HTTP 传输的首块早于完整段落结束；配合本地 XTTS `inference_stream` 实现，可证明此单段在合成时已有音频返回。网关默认仍为 `segmented`，真实流式模式须显式设置 `REALTIME_TTS_MODE=streaming` 并重启服务。

### 本机真实 XTTS 单段测量

2026-09-24 在 arm64、32 GiB 内存的 Mac（型号 Mac17,2）上，用操作系统合成的测试音色生成临时 WAV，只对本机 `127.0.0.1:18083` 上隔离运行的本分支 XTTS 服务请求同一句短中文。模型来自本机现有的 XTTS v2 缓存，Python 服务单进程、CPU 默认模式。测试结束已关闭隔离服务并删除临时音频。

| 运行条件 | 首块到达 | 片段完成 | PCM 块数 | 音频时长 |
|---|---:|---:|---:|---:|
| 冷启动（含模型加载） | 25,307 ms | 26,581 ms | 24 | 2,229 ms |
| 同进程第二次（模型已加载） | 859 ms | 1,876 ms | 20 | 1,856 ms |

这是各一次的开发机观测，不是 P50/P95；文本生成、网络云延迟、浏览器缓冲、扬声器实际出声及声音自然度均未计入。短句和系统音色不能代表正式资料问答。冷启动耗时明显；现在可在启动 XTTS 前设置 `TTS_PRELOAD_MODEL=1`，让模型加载发生于服务就绪前，并保留分段降级。不将第二次 859 ms 当作文档定义的完整处理首音时延。

### 本机整链路资料问答联调

同日用本机临时发布的一条测试资料（“报名材料需学生证。”）在浏览器资料模式提问“报名材料需要什么？”。资料原文、来源标题及版本正确显示，语音增量合成播放完成。首次请求页面记录：首次文字 239 ms、首块合成音频 24,687 ms、AudioWorklet 播放启动 24,691 ms。相同页面、同一认证 WebSocket 第二轮提问：首次文字 69 ms、首块合成音频 1,218 ms、播放启动 1,224 ms；播放过程中页面记录 2 次欠载。点击“打断回答”后状态变为“已停止回答”，未观察到该轮旧文本或音频再输出。联调后删除临时资料并停止服务。

这些是各一次、本机 CPU 与系统合成测试音色条件下的开发测量；AudioWorklet 播放启动不等于扬声器实际发声时刻。欠载说明此环境仍须做缓冲策略、模型预热和长句压力评估，不能据此宣称达到生产延迟指标。
