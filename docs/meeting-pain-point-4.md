# 第四痛点：无声纹样本的会议发言整理

## 2026-09-16 增强：边界、代表样本、复核与评估

本轮按原方案第七章第 7 节补充既有 FFmpeg + FunASR + CAM++ 链路，不引入新的在线模型，不需要 DeepSeek Key，不改变真实身份认证规则。

- **切片边界**：保留不足 1.2 秒的短发言，长段均匀切分至不超过 12 秒，避免丢失末尾不足 1.2 秒的内容；合并交叠静音范围，处理结尾静音，纯静音不再回退成整段发言。短片段仍转写，但不进入声纹候选匹配或匿名聚类，保持未知，供人工核对。
- **代表样本**：每个匿名组保留最初锚点和最多一个更新样本。明确归组且相似度至少达到 max(分组阈值, 0.90) 时更新；后续必须同时与两者一致。两者判断冲突时返回未知，不让更新样本逐步带偏整组。会议结束清空两份样本。每次比较最多增加到原先两倍。
- **歧义边界**：第二名即使略低于阈值，也参与分差检查，避免 0.73 对 0.71 被误当成明确匹配。这些阈值尚未用真实语料校准；更保守可能增加未知片段，不能据此声称准确率提升。
- **人工校正隔离**：筛选、图例和批量改名按“档案 ID / 本场名称 / 未知片段 ID”分组；同名不同档案不混改，未知片段不自动合并。逐段改名后立即按本场人工分组预览。批量合并目标若仍属于档案候选，先改为独立本场名称再合并，避免把人工改名误当成身份认证。
- **复核清单**：按组显示未知、短片段、档案候选、无效时间和低于 0.80 的相似度提示，并提供原音定位。0.80 仅为复核提示阈值，不是识别阈值或身份概率；提示数量不是错误率。原文中的疑问、否定、建议及暂定表述附加提醒，三种文档导出也保留提醒。
- **评估入口**：详情的“下载匿名分组评估数据”仅导出已保存片段的时间与匿名组号，不含转写、真实姓名、档案 ID、音频或未保存草稿。下面的命令将其与独立人工标注比较，不需要联网或 API Key。

在仓库根目录、安装了 NumPy/SciPy 的 Python 环境运行：

```sh
python -m services.evaluation.meeting --meeting meeting-anonymous-evaluation.json --reference manual.json
python -m unittest services.evaluation.test_diarization services.evaluation.test_corpus services.evaluation.test_meeting
```

`manual.json` 示例格式（这里只是格式示例，不是实际测得结果）：

```json
{"durationSeconds": 5, "reference": [{"start": 0.5, "end": 2, "speaker": "A"}, {"start": 2.5, "end": 4, "speaker": "B"}]}
```

人工标注必须独立于系统输出，时间单位为秒，允许同时说话的重叠区间。评估沿用最优一对一映射、collar=0、包含重叠的 DER 定义；每个未知片段作为独立假设簇，另报未知片段数，不把“未知”都当成同一人。单段分组可对齐得到低 DER，不意味着识别了真实身份。当前评估器最多支持每场 100 个标签，超限明确拒绝；它不执行 ASR 或 CAM++ 推理。比较修改前后须使用相同录音、人工标注、模型与硬件，并记录处理耗时和未知比例。

## 本轮可使用的流程

1. 在会议纪要页上传录音，保持“无样本自动区分发言人”开启，可不选任何声纹档案。
2. 处理完成后进入详情。“按发言人整理 · 原文依据”按本场会议分组，展开查看发言摘录、结论候选、待办候选。
3. 每条摘录包含片段 ID 和起止时间；有原录音时可点击试听。分类依据为原文关键词，保留否定和疑问，不把候选自动认定为会议决定。
4. 进入人工校正可重命名、合并发言组，也可逐片段改名拆开误分组、修改转写。保存后分组、原文依据和导出重新计算。
5. 保存会核对进入编辑时的内容指纹。其他页面已更新内容时返回业务码 409，当前草稿保留；可先“下载校正草稿”再重新打开最新纪要核对。草稿是本机 JSON 备份，当前不提供自动导入。
6. TXT、Markdown、DOCX 导出在勾选“整理后发言块”时附带按组原文及时间证据；关闭此选项则不附加。历史版本 API 的整理结果根据该版本片段生成，不读取当前片段替代旧证据。

## 归属与身份规则

- 匿名名称或人工名称只属于当前会议，不写入注册声纹库，不代表身份已核实。
- 档案比对结果是候选，即使有档案 ID 也不标记身份已核实。
- “未知发言人”各片段独立整理，不能因为名称相同而推断是同一人。
- 同名但不同档案 ID 的连续片段不合并。
- CAM++ 两个候选组分数差小于或等于 ambiguity-margin 时返回未知；缺失有效比较结果也不强行分配。
- 达到 max-speakers 后，不匹配的音频保持未知，不强制归入已有组。
- 待办中提到某人不等于那个人负责；仅显式分配句式提取负责人，含糊代词保持待确认。
- 全文中相同句子出现在不同发言人下时不猜来源；新增原文卡保留各自片段证据。

## 配置与升级

- meeting.diarization.threshold：现有阈值，默认 0.72。
- meeting.diarization.ambiguity-margin：默认 0.05，范围 0–1。是保守拒分规则，尚未用真实语料校准。
- meeting.diarization.max-speakers：默认 32，范围 1–128。
- 无数据库结构迁移。详情新增 correctionToken、speakerSummaries；人工校正请求必须携带 correctionToken。前后端需一起部署，旧页面需重新打开。
- 本轮独立于 DeepSeek 网关，不需要 API Key，原文分类在本地执行。
