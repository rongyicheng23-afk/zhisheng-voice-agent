# 第四痛点：无声纹样本的会议发言整理

2026-09-14。对应需求：没有预先注册声纹时，仍能按发言人整理观点、结论和待办；匿名分组与真实身份识别严格区分。

## 本轮可使用的流程

1. 在会议纪要页上传录音，保持“无样本自动区分发言人”开启，可不选任何声纹档案。
2. 处理完成后进入详情。“按发言人整理 · 原文依据”按本场会议分组，展开查看发言摘录、结论候选、待办候选。
3. 每条摘录包含片段 ID 和起止时间；有原录音时可点击试听。分类依据为原文关键词，保留否定和疑问，不把候选自动认定为会议决定。
4. 进入人工校正可重命名、合并发言组，也可逐片段改名拆开误分组、修改转写。保存后分组、原文依据和导出重新计算。
5. 保存会核对进入编辑时的内容指纹。其他页面已更新内容时返回业务码 409，当前草稿保留；可先“下载校正草稿”再重新打开最新纪要核对。草稿是本机 JSON 备份，当前不提供自动导入。
6. TXT、Markdown、DOCX 导出在勾选“整理后发言块”时附带按组原文及时间证据；关闭此选项则不附加。历史版本 API 的整理结果根据该版本片段生成，不读取当前片段替代旧证据。

## 归属与身份规则

- 匿名名称或人工名称只属于当前会议，不写入注册声纹库，不代表身份已核实。
- 档案比对结果是候选，即使有档案 ID 也不标记身份已核实。
- “未知发言人”各片段独立整理，不能因为名称相同而推断是同一人。
- 同名但不同档案 ID 的连续片段不合并。
- CAM++ 两个候选组分数差小于或等于 ambiguity-margin 时返回未知；缺失有效比较结果也不强行分配。
- 达到 max-speakers 后，不匹配的音频保持未知，不强制归入已有组。
- 待办中提到某人不等于那个人负责；仅显式分配句式提取负责人，含糊代词保持待确认。
- 全文中相同句子出现在不同发言人下时不猜来源；新增原文卡保留各自片段证据。

## 配置与升级

- meeting.diarization.threshold：现有阈值，默认 0.72。
- meeting.diarization.ambiguity-margin：默认 0.05，范围 0–1。是保守拒分规则，尚未用真实语料校准。
- meeting.diarization.max-speakers：默认 32，范围 1–128。
- 无数据库结构迁移。详情新增 correctionToken、speakerSummaries；人工校正请求必须携带 correctionToken。前后端需一起部署，旧页面需重新打开。
- 本轮独立于 DeepSeek 网关，不需要 API Key，原文分类在本地执行。

## 验证与限制

自动化覆盖原文和时间定位、匿名与档案隔离、未知组分离、校正后重算、歧义拒分、组数上限、旧草稿拒写、缺失版本拒写、接口冲突码、三种导出与开关、前端冲突草稿保留及构建。

最终验证：Java 80 项、前端 29 项测试通过，Java 打包和前端生产构建成功，Git 差异格式检查通过。前端既有的大包体积、Browserslist 和 CSS 弃用提示仍存在。页面尚未执行真实浏览器视觉验收。

这是原文摘录与规则分类，不是经过人工确认的语义总结。声学边界仍使用已有 FFmpeg 切片与 CAM++ 比较，未新增重叠语音分离模型，不能承诺真实多人录音的识别准确率。数据库锁与事务测试使用模拟依赖，尚不能代替真实 MySQL 并发验收；未执行真实会议音频端到端评测。
