# 第四批：匿名会议聚类适配与阈值语义修正

2026-09-12。对应解决方案第七章第 7 节：复用既有 FFmpeg 切片、FunASR 转写和 CAM++ 聚类，不把匿名分组当作真实身份识别。

## 已查明的问题

旧代码定义匿名分组阈值 0.72，却同时接受声纹比对服务的 samePerson=true。当前 CAM++ 服务的该布尔值采用 0.25 阈值，所以低于 0.72 的分数仍可能合并。新建匿名组时还保存了未被接受的最高比较分，页面以百分比“匹配度”显示，容易被误读为该组的可信度。

## 改动与决策

- 新增 SpeakerDiarizationAdapter 会话接口及 CAM++ 实现，接入既有会议片段循环；每场会议独立会话、独立编号与代表音频，正常/异常退出都关闭会话并释放引用。代表音频仍仅为每组首个片段，不引入未经评估的更新策略。
- 匿名合并只看当前会议阈值与有效相似度，不复用身份比对的 samePerson 布尔值。默认沿用代码中的 0.72，可通过 meeting.diarization.threshold（环境变量 MEETING_DIARIZATION_THRESHOLD）配置，启动时校验 0–1。
- 多个候选同时达标时取最高分；分数相等保持先出现的组，编号仍依出现顺序生成。
- 新建组的 matchScore 为 null，不再保存被拒绝的最高分。比较结果缺失/超出 [-1,1] 且没有有效匹配时标记“未知发言人”，不把缺少证据解释为发现新说话人。比较请求异常仍让当前业务报错，不静默伪造成功。
- 页面说明标签只在本场会议中表示匿名分组；档案候选匹配需人工确认。分数显示为三位小数“声学相似度（非身份概率）”，不再显示成百分比。

## 验证与边界

- Java 27 项测试通过（新增 8 项），覆盖低阈值绕过、0.72 边界、最高分选择、缺失/异常分数、会议隔离、会话关闭、比较失败和非法配置。
- 前端生产构建、git diff --check 通过；已有体积/CSS/Browserslist 警告及 Mockito 动态加载测试代理警告仍存在。本轮未启动真实模型或进行浏览器端到端测试。
- 这些测试使用比较服务替身，证明分组决策逻辑，不证明真实会议识别质量。
- 没有改变有授权声纹档案的原有候选匹配逻辑；没有改数据库结构、重跑历史、覆盖人工修订或删除录音。旧历史中的分数语义不会被自动修正，需人工复核。
- 0.72 不是经过本项目标注集校准的最优阈值。修正绕过后可能产生更多匿名组，需要真实多说话人标注集、DER 与人工修订次数对照后才能评价效果。
- 本轮只抽取匿名聚类子步骤；FFmpeg 边界检测与 ASR 仍在会议业务层。完整端到端 Diarization Adapter、边界优化、代表片段更新及 DER 评估尚待后续。
- 当前切片策略仍无法可靠处理重叠发言或一个片段内多人轮换。本轮不声称该痛点已完整解决。
