## 二、立项依据

### （一）研究目的

当前语音处理工具多偏向单点功能，用户在课堂和会议场景下往往需要在“录音转写、实时记录、语音合成、声纹比对、纪要整理”等多个工具之间切换，结果也难以统一保存和复用。本项目拟在现有原型基础上，进一步完善一个面向会议与课堂场景的多语音智能处理平台，重点解决语音处理链路分散、结果不可追溯、纪要结构化不足和多模块协同不强等问题。

### （二）研究内容

1. 完善统一的前后端与模型服务协同架构，实现语音处理能力集中管理。
2. 优化离线识别与实时识别功能，支持音频上传、麦克风采集、历史记录保存与回看。
3. 实现参考音频驱动的文字转语音功能，支持语言和情感参数配置。
4. 实现声纹比对与发言人样本管理，为会议纪要中的发言人匹配提供基础。
5. 深化智能纪要功能，实现摘要、关键词、待办提取，以及片段识别、人工校正和多格式导出。

### （三）国内外研究现状和发展动态

近年来，自动语音识别、流式识别、说话人验证、多语种语音合成和会议语音理解等技术发展迅速，相关开源模型和工具不断成熟，已具备较好的工程落地基础。但从产品形态看，当前很多系统仍偏向单项功能展示，缺少围绕真实会议和课堂场景的完整闭环，尤其是在历史留存、发言片段组织、待办提取、人工校正和结果导出等方面仍有明显提升空间。因此，将现有开源语音能力整合成统一的软件平台，具有较强的研究意义和应用价值。

### （四）创新点与项目特色

1. 将离线识别、实时识别、文字转语音、声纹比对和智能纪要整合到同一平台。
2. 以软件系统为核心，形成“前端交互 + 后端调度 + 模型服务 + 数据存储”的完整闭环。
3. 在全文转写基础上进一步生成摘要、关键词、待办，并支持发言人片段组织。
4. 支持历史留存、人工校正和 TXT/Markdown/DOCX 导出，贴近真实使用场景。

### （五）技术路线、拟解决的问题

项目采用“Vue3 前端 + Spring Boot 后端 + FunASR/XTTS/CAM++ Python 服务 + MySQL + MinIO”的技术路线。前端负责上传、录音和展示，后端负责鉴权、接口编排和结果落库，Python 服务分别承担离线识别、实时识别、文字转语音和声纹比对，MySQL 保存结构化结果，MinIO 保存音频文件。项目拟重点解决多语音功能分散、处理结果难追溯、会议纪要结构化不足、发言人组织困难以及长音频稳定性仍需优化等问题。

### （八）已有基础

#### 1. 与本项目有关的研究积累和已取得的成绩

目前项目已经完成较完整的原型系统开发，前端已实现录音转文字、文字转语音、智能纪要、实时语音和声纹对比五个主要功能页面；后端已实现用户登录鉴权、REST 接口、WebSocket 代理、历史记录入库和对象存储管理；数据库已完成用户、录音历史、TTS 历史、声纹历史、发言人档案、会议纪要和会议片段等核心表设计。项目已具备继续深化研究的现实基础。

#### 2. 已具备的条件，尚缺少的条件及解决方法

项目已具备可运行的前后端代码、模型服务环境、数据库和对象存储环境，也已有实际历史记录和样例数据，可支持测试与答辩展示。当前不足主要在于长音频稳定性、发言人样本规模和纪要抽取质量仍有提升空间。后续将通过音频分段、链路优化、样本补充、规则改进和页面性能优化等方式持续完善。
