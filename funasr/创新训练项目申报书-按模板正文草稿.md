## 二、立项依据

### （一）研究目的

随着线上线下混合教学、课程录音整理、小组讨论归档和会议纪要生成需求不断增加，语音信息处理已从单一“把语音转成文字”的技术问题，扩展为“如何围绕真实场景构建一套可持续使用的软件系统”的工程问题。当前很多工具往往只支持单项能力，如只做录音转写、只做语音合成或只做说话人识别，用户在实际使用中仍需要在多个平台之间来回切换，既增加了操作复杂度，也不利于结果的统一管理和后续复用。

本项目的研究目标不是简单调用单个模型接口，而是在现有“特辣油语音工厂”原型基础上，进一步完善一个面向会议和课堂场景的多语音智能处理平台。一方面，通过统一前后端架构把离线识别、实时识别、文字转语音、声纹比对和智能纪要等能力组织成完整流程；另一方面，通过历史记录、对象存储、结构化结果和人工校正机制，使语音处理结果真正具备可回溯、可编辑、可导出的应用价值。项目最终希望形成一个既可用于教学展示和竞赛答辩，也具备实际使用意义的语音应用系统。

### （二）研究内容

本项目围绕“多语音能力融合”和“会议/课堂场景落地”两个核心方向开展研究，主要内容包括以下五个方面：

1. 构建统一的多语音处理平台架构。以前端页面为统一入口，后端作为业务中台，联通 FunASR 语音识别服务、XTTS 语音合成服务和 CAM++ 声纹比对服务，并通过 MySQL 与 MinIO 形成“处理结果 + 原始文件”双轨存储机制。

2. 完善离线与实时语音识别链路。离线识别支持上传常见音频格式并保留识别历史；实时识别支持浏览器麦克风采集、分片传输、WebSocket 实时转写和结束后落库保存，满足课堂发言、会议讨论和演示场景需求。

3. 实现参考音频驱动的文字转语音功能。用户可上传参考音频、输入文本并选择语言和情感参数，系统调用 XTTS 服务生成目标语音，并保存参考音频、生成音频及相关参数，形成完整历史记录。

4. 实现声纹比对与发言人样本管理。系统支持上传两段音频进行相似度计算，并输出“是否为同一人”的判断结果；同时支持建立发言人样本档案，为后续会议纪要中的发言人匹配提供基础。

5. 强化智能纪要功能。系统不仅生成全文转写，还自动抽取摘要、关键词和待办事项；在选择发言人档案后，还会对原始音频进行静音检测、片段切分、逐段识别和声纹匹配，进一步形成“发言片段”和“整理后发言块”两层结构，并支持人工校正及 TXT、Markdown、DOCX 多格式导出。

### （三）国内外研究现状和发展动态

近年来，国内外语音信息处理技术发展较快，自动语音识别、流式语音识别、说话人验证、多语种语音合成和会议摘要生成等方向都取得了明显进展。以端到端语音识别为代表的技术路线逐渐成熟，语音识别系统已经能够在较短延迟下完成普通中文场景的转写任务；同时，多语种语音合成和说话人验证技术的开源化，也显著降低了相关应用系统的开发门槛。

从国内发展看，面向工业应用的开源工具和模型使语音识别服务部署更加便捷，非自回归识别、流式识别、端点检测和标点恢复等能力能够较好地支撑工程落地。从国外发展看，多语种语音克隆、说话人表征学习和会议语音理解也在持续推进，参考音频驱动的语音合成和轻量化声纹识别方案为应用侧集成提供了现实基础。

但从实际产品形态看，目前很多系统仍然偏向单点功能展示，往往强调某一项模型能力，却缺少围绕真实学习和办公场景的完整闭环。尤其是在会议和课堂场景中，仅有“转写结果”往往还不够，还需要进一步解决历史可追溯、发言片段组织、待办提取、人工校正和文档导出等问题。因此，将现有开源语音能力整合为一个可持续使用的软件平台，仍具有较强的研究意义和应用价值。

### （四）创新点与项目特色

1. **多语音能力一体化整合。** 项目不是单一识别或单一合成 Demo，而是把离线识别、实时识别、文字转语音、声纹比对和智能纪要统一纳入一个平台中，实现了多能力联动。

2. **以软件系统为中心的工程实现。** 项目重点不在单项模型指标比拼，而在于通过前后端分离、多服务协同、统一鉴权、数据落库和对象存储，形成完整的软件工程闭环，更符合创新训练项目对“研究与开发结合”的要求。

3. **面向会议和课堂场景的结构化纪要机制。** 在全文转写基础上，系统进一步生成摘要、关键词、待办事项，并在具备发言人样本时，通过音频切分与声纹匹配生成发言片段和发言块，这比单纯展示一段转写文本更贴近真实应用。

4. **可追溯、可校正、可导出的结果体系。** 所有关键结果都可以保存历史、下载音频、查看详情、人工校正并导出为多种文档格式，既方便教学展示，也便于后续继续整理和复查。

5. **在现有原型基础上的持续深化。** 本项目并非从零起步，而是建立在已完成原型和已打通运行链路的基础上，后续研究将聚焦于稳定性优化、场景适配和成果规范化，更具可执行性。

### （五）技术路线、拟解决的问题

本项目采用“浏览器前端采集/上传 + Spring Boot 统一业务中台 + Python 语音服务 + MySQL + MinIO”的总体技术路线。前端使用 Vue3 和 TypeScript 构建用户交互页面，负责音频上传、实时录音、结果展示和历史管理；Spring Boot 后端负责用户登录鉴权、接口编排、数据落库、文件上传下载以及对模型服务的统一调用；Python 服务层分别承担离线语音识别、实时 WebSocket 转写、文字转语音和声纹比对功能；MySQL 保存用户、历史记录、纪要结果与片段信息，MinIO 保存原始音频、生成音频和会议切分片段。

在离线识别部分，系统基于 FunASR 完成语音识别，并结合端点检测与标点恢复提升转写结果的可读性；在实时识别部分，浏览器采集麦克风音频后按固定大小切片，由 Java 后端代理转发至 FunASR WebSocket 服务，实现边录边转写；在文字转语音部分，系统调用 XTTS 服务，基于参考音频和文本生成目标语音；在声纹比对部分，系统使用 CAM++ 服务计算两段音频的相似度并给出判定结果；在智能纪要部分，系统先完成全文识别，再进行句子切分、关键词抽取和待办提取，在选定发言人档案的情况下，进一步使用 `ffprobe` 和 `ffmpeg` 完成音频时长获取、静音检测和分段切片，对各片段再次识别并调用声纹服务进行匹配，最终生成可读性更强的发言人纪要。

项目拟重点解决以下几个问题：

1. 多个语音功能分散在不同工具中，用户操作链路长、结果难以统一管理的问题。
2. 单次处理结果缺乏历史留存、无法回放与追溯的问题。
3. 会议和课堂场景下仅有全文转写、缺少结构化纪要与待办提取的问题。
4. 发言人信息难以组织，音频片段无法与具体人员对应的问题。
5. 长音频场景下稳定性与处理效率仍有优化空间的问题。

### （八）已有基础

#### 1. 与本项目有关的研究积累和已取得的成绩

本项目已经完成较完整的原型系统开发，具备继续开展创新训练研究的现实基础。当前系统已形成“前端展示层 + Java 业务层 + Python 模型服务层 + MySQL + MinIO”的完整架构，前端已实现录音转文字、文字转语音、智能纪要、实时语音和声纹对比五个主要页面，并提供历史记录抽屉、发言人档案管理、纪要详情页、时间轴联动和导出等交互功能。后端已实现用户注册登录、JWT 鉴权、REST 接口、WebSocket 代理、历史记录入库、对象存储管理以及会议纪要人工校正等能力。数据库层已完成用户、录音历史、TTS 历史、声纹比对历史、发言人档案、会议纪要和会议片段等核心数据表设计。

从功能链路看，项目已经打通离线识别、实时转写、参考音频驱动的文字转语音、声纹比对以及智能纪要生成等关键流程，并能把原始音频、结果音频和结构化文本结果统一存储和回看。从当前运行情况看，项目相关服务已能够在本地环境中协同运行，说明本项目不是停留在方案层面，而是已经具备可继续深化研究和迭代优化的实际平台基础。

#### 2. 已具备的条件，尚缺少的条件及解决方法

目前项目已经具备以下条件：一是已有可运行的前后端代码和 Python 模型服务代码，系统总体架构清晰；二是本地环境已经配置 MySQL、MinIO、FunASR、XTTS、CAM++ 等运行依赖；三是已有历史记录、样例音频和功能页面，可支撑项目演示、测试和后续改进；四是系统已支持多种业务结果的存储、下载和导出，有利于形成规范成果。

当前仍存在以下不足：第一，长音频场景下的处理效率和稳定性仍需优化，部分较长音频可能出现超时；第二，发言人匹配效果依赖于样本音频质量和数量，目前还需要继续积累更规范的样本数据；第三，智能纪要的关键词与待办提取规则还可进一步优化，以提升结果准确性与可读性；第四，前端静态资源体积偏大，后续仍需进行页面性能优化。

针对上述问题，项目计划从以下方面解决：一是通过音频分段、链路超时优化、服务参数调整等方式提升长音频稳定性；二是补充多说话人样本数据和典型会议/课堂录音，提升发言人匹配效果；三是继续优化纪要抽取规则，并结合人工校正机制提升结果质量；四是通过按需加载和页面结构优化改善前端构建体积与页面体验。
